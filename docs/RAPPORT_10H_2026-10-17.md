## 2. Piste A — graphe, données, SQL

### 2.1 Schéma et invariants

- `NodeKind.EVENT` et `NodeKind.PARAM_STATE` ajoutés.
- `LIQUIDATED_IN` ajouté au catalogue (35 types).
- `valid_from_block` / `valid_to_block` deviennent des champs de première classe du `RelationRecord` ; le writer les persiste dans des colonnes indexables.
- `finality` par défaut : **PENDING**, plus `FINALIZED`.
- `insert_relation` legacy déprécié (`DeprecationWarning`), `insert_relation_record` reste le writer validant.
- Cinq triggers SQL G1–G5 + vues `prop_edge`/`prop_step` : la non-propagation est refusée par le moteur, pas seulement par Python.
- Les triggers refusent `UPDATE`/`DELETE` sur les tables append-only.

### 2.2 Ingestion

- Source : Aave v3 Pool Base `0xA238Dd80C259a72e81d7e4664a9801593F98d1c5`.
- RPC : `https://base.gateway.tenderly.co` (seul endpoint gratuit testé qui sert l’historique ; `mainnet.base.org` → 429).
- Fenêtre : 30 000 blocs, ~15 000 événements.
- Raw store : `D:/orvyren_10h_2026-10-17/raw/` (JSONL.gz + manifest + sha256).
- Watermark : `base-aave-v3-pool`, reprise idempotente.
- 8 types peuplés : `HOLDS`, `DEPOSITED_IN`, `OWES`, `COLLATERALIZES`, `PART_OF`, `DEPLOYED_ON`, `IS_A`, `CONSTRAINS`.
- `LIQUIDATED_IN` est au catalogue mais **aucune liquidation** dans la fenêtre : zéro ligne, aucun événement inventé.
- Les timestamps sont interpolés entre deux blocs exacts ; le bloc reste l’autorité PIT.

### 2.3 API read-only

- `exposure` (Q1), `pit` (Q4), `timeline` (Q5), `provenance` (Q6), `concentration` (Q7), `permissions` (Q8), `snapshot`.
- Ouvre SQLite en `mode=ro` : aucune migration paresseuse, aucune écriture.
- Q8 retourne `NOT_INGESTED` quand aucune permission n’a été ingérée.
- Chaque réponse porte `latency_ms` et `mode`.

### 2.4 Snapshot UI

## 3. Piste B — agents, mémoire, UI, sécurité

### 3.1 Tool calling natif + fallback

- `contracts.ToolCall`, `ToolTurn`, `TOOLCALL_SCHEMA_ID=orvyren/toolcall/v1`.
- `tool_spec()` : JSON Schema strict, `additionalProperties=false`, `execute_intent` refusé.
- `parse_tool_calls()` : shape OpenAI + shape rejoué.
- `ToolTurnRunner` : propose → valide les args → exécute via `ToolRegistry` → finalise en JSON strict.
- Mode natif `tools` + `tool_choice=auto` ; fallback JSON strict journalisé, jamais silencieux.
- Rejeu bit-identique via `RecordedBackend`.
- 19 tests dédiés.

### 3.2 Outils graphe réels

- `graph_query`, `graph_path`, `graph_snapshot` branchés sur `graph/api.py`.
- `graph_path` retourne `status: OK` avec 0 chemin sur le slice Aave (aucune arête `DEPENDS_ON`/`AFFECTS`) ; le code Q2 est testé sur fixtures.
- 17 tests dédiés.

### 3.3 Mémoire

- `FTSMemory` (SQLite FTS5, ordre déterministe).

- Chaîne d’outils bornée à 3 appels (`E_TOOL_CHAIN_LIMIT`), budgets existants conservés.
- 9 tests dédiés.

### 3.4 UI 3 panneaux

- Résolution : LIVE (API) > REPLAY (`evidence/ui_snapshot.json`) > FIXTURE (maquette) > « SOURCE MANQUANTE ».
- Routes `/panels` et `/api/panels`.
- 8 tests dédiés ; 26 tests panels/e2e/graph tools vérifiés ensemble.

### 3.5 Sécurité documentaire

- Les 13 `SUBMIT` portent `key_material: "never recorded"` ; la clé de démo est humaine, hors agent.

## 5. Limites à ne pas masquer

1. **EVAL N=0** : aucun gain de décision mesuré. Le harnais existe ; le code exige N≥100 pour un test de supériorité. Ne pas écrire « EVAL concluante ».
2. **Q8 = NOT_INGESTED** : pas de Safe/Zodiac dans ce slice. L’écran doit le dire.
3. **`LIQUIDATED_IN` = 0 ligne** : le type existe, aucune liquidation dans la fenêtre. Ne pas prétendre l’avoir démontré.
4. **Q2 `graph_path` = OK mais 0 chemin** : l’API Q2 existe ; le slice Aave n’a pas d’arêtes `DEPENDS_ON`/`AFFECTS`, donc l’outil retourne 0 ligne honnêtement.
5. **Pas de 10⁵** : 15 000 événements. La promesse publique doit rester **10k+**.
6. **Pas de multi-chaîne, pas de SQL/PGQ, pas de graph DB** : choix assumés.
7. **Base de 50 Mo hors dépôt** : le snapshot versionné est la pièce auditables ; la base complète se régénère par script.
8. **Pas de soumission** : les six pièces ne sont pas encore déposées.
